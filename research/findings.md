# Investigation ledger

- Target: ScreenBrush, macOS App Store ID 1233965871. Official website: https://screenbrush.app/. Published feature reference: https://apps.apple.com/us/app/screenbrush/id1233965871?mt=12.
- Toolkit: https://github.com/morluto/rea. Followed its AGENTS.md and reverse-engineering skill, including connection recovery.
- Observation: host is WSL2 Linux, with X/Wayland display variables. No ScreenBrush app bundle was supplied. There are no connected REA MCP tools in this session.
- Evidence boundary: published descriptions support the feature selection. No ScreenBrush binary was decompiled and no original runtime behavior was observed. There are no native REA Evidence IDs to cite. A website capture would not establish native drawing behavior.
- Design choice: Electron transparent always-on-top canvas plus a separate interactive toolbar. This is an independent implementation, not a recovered ScreenBrush source tree. The REA repository is an investigation tool rather than the UI framework.
- Unresolved: exact visual/behavioral parity, native fullscreen overlays, platform shortcuts, multi-monitor operation. These require the target app artifact and target desktop testing.
- REA CLI 6.8.0 successfully launched with existing Node 22.23.4. Its readiness check reported missing client registration and no native analysis engine. Machine-specific diagnostics are excluded from Git. No agent configuration was changed. Native analysis remains blocked on the missing ScreenBrush artifact and analysis provider.
- Validation: four renderer tests cover history branching, reversible clear, transient laser strokes, text, PNG export dispatch, HiDPI sizing, and ellipse geometry. JavaScript syntax checks pass. Dependency installation with Electron 45.2.1 reports zero known vulnerabilities.
- Desktop validation: Electron loaded both windows under WSLg. Real canvas pixel assertions for drawing, clear, undo and whiteboard passed. WSLg reported `isAlwaysOnTop() === false` for both windows, so native overlay parity remains unverified. Observed GPU shared-image failures were fixed for WSL by using software rendering. The toolbar was captured and visually inspected.
- Prepared the official checksum-verified Electron Windows x64 runtime, packaged the app, and launched it from `%LOCALAPPDATA%\ScreenBrush-Rebuild`. PowerShell confirmed the native process remained running after startup. The toolbar has the overlay as its parent to preserve its stacking order. End-user drawing over other Windows applications still needs confirmation; process startup alone does not establish that behavior.
